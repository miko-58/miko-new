# ユーザー同士のチャット

市民が地図またはリストでヒーローを選び「チャットする」で開始します。
ヒーローは市民から届いた相談を一覧で確認して返信します。会話画面の「依頼を終了」および再開は、会話を開始した市民だけが利用できます。
同じ相手との再開では同じ部屋と履歴を使います。終了した会話は一覧に残りますが、再開するまでは送信できません。

## 保存先と制限

- `directChats/{pairId}`: 2人のUID、表示名、開始時の役割（`participantRoles`）、依頼者UID（`requesterUid`）、active/closed、作成・更新日時。
- `directChats/{pairId}/messages/{messageId}`: 送信者UID、本文、送信日時。

開始・再開・終了はFirestoreトランザクションで実行します。Firestoreルールでも、市民がヒーローへ開始すること、依頼者だけが終了・再開することを要求します。複数の相手との会話は並行して開始できます。直接の書き込みでも第三者による閲覧・送信は認めません。
プロフィールの実績は会話終了では加算しません。

## 反映前の確認

1. Java 21以降のある環境で、ルートから `npm run test:chat` を実行してください。
2. `firebase/firestore.rules` を対象のFirebaseプロジェクトに反映してください。コンソールのFirestore Database → ルールでファイル全体を貼り付けて公開するか、対象プロジェクトを確認して `firebase deploy --only firestore:rules --project <プロジェクトID>` を実行します。
3. アプリを反映し、別アカウントで開始・送信・終了・再開を確認してください。複数の相手との会話を同時に開始できることも確認します。

新しい保存先は初回の開始時に自動作成します。手動でコレクションを作る必要はありません。新しい会話は `v2_` で始まるIDに保存され、開始時の役割を保持します。ルールが未反映だと新しい会話の取得・開始は失敗します。

## 以前の投稿チャット

`helpPosts` 以下の投稿チャットは削除・移行していません。開始時の役割を持たない旧形式の `directChats` も削除・移行していませんが、新しいメッセージ一覧には表示しません。旧会話URLはメッセージ一覧に移動します。
投稿ごとに分かれた過去の会話をユーザー単位に統合する場合は、別途移行が必要です。
旧投稿機能のルールやデータは他の機能への影響を避けるため残しています。
