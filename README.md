# Nearu

## 📌 概要

**「助けたい人」がヒーローになる、新しい助け合いアプリです。**

Nearuは、「誰かを助けたい」という気持ちと、「ちょっと助けてほしい」という困りごとをつなぐサービスです。

従来のように困っている人がHelpを投稿して待つのではなく、**助けたい人が先にヒーローとしてマップに登録される**仕組みを採用しています。

市民はマップに表示されたヒーローを探し、自分の困りごとに合った相手にチャットで助けを依頼できます。

誰かを助けたいときも、誰かの力を借りたいときも。

Nearuは、誰もが助ける側にも、助けられる側にもなれる場所を目指しています。

---

## 🎯 開発背景

当初は、困っている人がHelpを投稿し、近くの人が助けに行く仕組みを考えていました。

しかし、開発を進める中で、次のようなアドバイスをいただきました。

- 一瞬で終わる困りごとは、投稿して待っている間に解決してしまう
- 報酬がなければ、わざわざ助けに行く人を集めるのは難しい

そこで、発想を逆転させました。

**「困っている人を集めるのではなく、助けたい人を先に集めよう」**

この考えから、ヒーローが自分の得意なことを登録し、マップ上で助けを必要としている人を待つ仕組みが生まれました。

さらに、ゲームのような世界観をUIに取り入れ、助け合いをもっと身近で楽しい体験にすることを目指しました。

## ✨ 主な機能

### 🦸 ヒーロー・市民の選択

登録時に役割を選択し、プロフィールを入力してGoogleアカウントでログインします。

- **ヒーロー**：誰かを助けたい人
- **市民**：助けを必要としている人

### 🦸 ヒーロー登録

ヒーローは、名前・性別（「回答しない」も選択可能）・得意なこと・希望する報酬（ほしいもの）を登録できます。得意なことは選択肢から1つ選ぶか、自由入力で設定します。

例えば、

- 重い荷物を運ぶ
- 道案内をする
- 買い物をサポートする
- スマホ・PCの使い方を教える

など、自分にできることを活かして誰かを助けられます。

希望する報酬には「無償・気持ちで」「お礼のお菓子」「コーヒー1杯」「相談して決める」などを選べます。

ブラウザで位置情報を取得できたヒーローは、登録時に保存した位置でマップに表示されます。

### 🗺️ ヒーローマップ

ヒーローを地図・リストの2つの表示で探せます。位置情報を許可すると、自分の現在地も地図に表示できます。

地図ではヒーローの名前と得意なことを確認でき、リストでは性別や希望する報酬も確認できます。

ヒーローの表示位置は登録時に保存した位置です。現在の居場所や、すぐに対応できるかどうかはチャットで確認してください。

### 🤝 チャットで助けを依頼

市民はヒーローを選んでチャットを開始し、助けを依頼できます。

ヒーローは届いた相談を確認し、対応できる内容をチャットでやり取りします。

**基本的な流れ**

1. ヒーローがプロフィールを登録し、位置情報の取得を許可
2. マップにヒーローが表示される
3. 市民がヒーローを選択してチャットを開始
4. 困りごとや待ち合わせ場所を相談
5. 助け合いを実施
6. 市民がチャットの「解決した」から撮影・評価画面を開く
7. 外カメ・内カメの写真と評価を送信し、チャットを終了

### 💬 チャット

市民とヒーローの間でメッセージをやり取りできます。

待ち合わせ場所や困っている状況など、助け合いに必要な情報を相談できます。

メッセージ一覧から会話を開けます。終了したチャットの履歴も残り、依頼を始めた市民が再開できます。

### 📸 BeReal風撮影・評価機能

**助け合いが完了した記録を、思い出として残す機能です。**

助け合いが終わった後に、市民が外カメと内カメを切り替えて1枚ずつ撮影し、1〜5つ星の評価とともに送信します。写真2枚と評価の選択が、解決を送信するために必要です。

写真はヒーローのマイページに「助け合いの思い出」として表示されます。

### 👤 マイページ

登録したプロフィールを確認できます。ヒーローには助けた回数・評価をもらった数・助け合いの思い出、市民には助けられた件数が表示されます。

市民は「渡せる報酬」を任意で入力・保存できます。設定メニューからログアウトもできます。

### 🎮 ゲーム風UI

Nearuでは、ヒーローという設定やゲーム風のデザインを取り入れています。

単なる困りごとの解決だけではなく、誰かを助けること自体を楽しい体験にすることを目指しています。

## 📱 動作条件

- **ログイン**：Googleアカウントとインターネット接続が必要です。Googleログインのポップアップを許可してください。
- **位置情報**：ヒーローの位置登録や自分の現在地表示には、ブラウザで位置情報の利用を許可してください。位置情報を保存できなかったヒーローはマップ・リストの表示対象になりません。
- **撮影**：ブラウザのカメラ利用を許可してください。外カメ・内カメを使い分けるには、対応するカメラを備えた端末が必要です。実際に選ばれるカメラは端末・ブラウザによって異なります。
- **アクセス方法**：カメラ・位置情報を使う場合は、HTTPSまたは開発端末の `localhost` でアクセスしてください。スマートフォンから開発用PCのHTTPアドレスを開くと、これらの機能を利用できない場合があります。

## 🛠️ セットアップ

このリポジトリは npm workspaces のモノレポ構成です。

`frontend` / `backend` の依存関係を、ルートの1つの `package-lock.json` で管理しています。

### 必要な環境

- Node.js：`>=24.21.0 <25`
- npm：`>=11.19.0 <12`

### 環境変数の設定

`backend/.env.example` を参考に、`backend/.env.local` を作成してください。既存のファイルがある場合は上書きせず、必要な設定を確認してください。

- **Firebase Admin SDK**：`FIREBASE_PROJECT_ID`、`FIREBASE_CLIENT_EMAIL`、`FIREBASE_PRIVATE_KEY` を設定します。バックエンドの起動に必要です。
- **Cloudinary**：`CLOUDINARY_CLOUD_NAME`、`CLOUDINARY_API_KEY`、`CLOUDINARY_API_SECRET` を設定します。写真のアップロード・表示に必要です。
- **Azure Storage**：過去にAzureへ保存した写真を表示する場合のみ、サンプルにあるAzure用の設定が必要です。

秘密鍵やAPIシークレットはGitにコミットせず、フロントエンドにも設定しないでください。接続情報はプロジェクトの管理者に確認してください。

フロントエンドのFirebase接続先は `frontend/src/lib/firebase.ts` に設定されています。接続先では、Firebase AuthenticationのGoogleログインとCloud Firestoreを利用できる必要があります。別のFirebaseプロジェクトを使用する場合は、フロントエンドとバックエンドの接続先を合わせてください。

### インストール・起動

**必ずリポジトリのルートで**以下を実行してください。

```bash
npm install
npm run dev
```

フロントエンドとバックエンドが同時に起動します。

- フロントエンド：`http://localhost:5173`
- バックエンド：`http://localhost:3000`

開発時の `/api` リクエストは、フロントエンドからバックエンドへ転送されます。バックエンドのポートを変更する場合は、`frontend/vite.config.ts` の転送先も合わせて変更してください。

依存関係のインストール・追加はルートから行い、`frontend/` や `backend/` に個別の `package-lock.json` を作らない運用にしてください。ロックファイルを分けると、依存関係の管理が一致せず、他の開発環境でエラーの原因になる可能性があります。

特定のワークスペースに依存関係を追加する場合も、ルートで実行します。

```bash
npm install <パッケージ名> --workspace=frontend
npm install <パッケージ名> --workspace=backend
```

### 開発用コマンド

すべてリポジトリのルートで実行してください。

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | フロントエンド・バックエンドを同時に起動 |
| `npm run dev:frontend` | フロントエンドだけを起動 |
| `npm run dev:backend` | バックエンドだけを起動 |
| `npm run build` | フロントエンド・バックエンドをビルド |
| `npm run typecheck` | フロントエンドの型チェックとビルド、バックエンドの型チェック |
| `npm run lint --workspace=frontend` | フロントエンドをOxlintでチェック |
| `npm run preview --workspace=frontend` | ビルド済みフロントエンドをローカルで確認 |
| `npm run start` | ビルド済みバックエンドを起動 |
| `npm run test:chat` | Firestoreエミュレーターでチャット関連のテストを実行 |
| `npm run test:participation` | FirestoreエミュレーターでHelp参加・完了処理のテストを実行 |

`preview` と `start` は、先に `npm run build` を実行してください。`preview` はフロントエンドの確認用で、開発サーバーの `/api` 転送設定を利用する起動方法は `npm run dev` です。

Firestoreエミュレーターを使うテストにはJavaの実行環境が別途必要です。テスト用設定は `firebase.test.json` にあり、Firestoreのポート `8089` を使用します。
